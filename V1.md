# V1: Capture (Local-First Core)

**Goal:** prove the core loop on plain notes: *extract decisions, store them, find them, flag contradictions.* No cloud, no models, no accounts.

## 1. Scope
**In:** Markdown/text ingestion, rule-based decision extraction, SQLite storage, TF-IDF search, three conflict heuristics, Markdown report, CLI, tests.
**Out:** LLMs, connectors, UI, users, real-time alerts (V2+).

## 2. Users and stories
- *Tech lead:* "Show me every decision about the orders database."
- *Engineer:* "Did we ever decide something that conflicts with this?"
- *Manager:* "Give me a report of contradictions in last quarter's notes."

## 3. Functional requirements
1. Ingest a file or folder of `.md/.txt`; incremental (skip unchanged by SHA-1).
2. Extract decision sentences with a confidence (strong phrases 0.9, weak 0.5).
3. Date each decision from filename `YYYY-MM-DD` or file mtime.
4. Search decisions by keywords.
5. Detect conflicts between decisions: `option_swap`, `polarity_flip`, `number_change`; label `supersedes?` when the newer date differs.
6. Emit a Markdown report.

Non-functional: stdlib only, runs in under 1 second for 10k sentences, deterministic, no network.

## 4. Architecture
```
files -> Ingestor -> Extractor -> SQLite(docs, decisions)
                                      |
                          Search (TF-IDF)   Conflict Engine -> Report
```
| Component | Responsibility |
|---|---|
| Ingestor | Walk paths, hash files, skip unchanged, replace stale rows |
| Extractor | Sentence split; regex strong/weak decision patterns |
| Store | SQLite tables `docs(path,date,sha)` and `decisions(id,path,date,text,confidence,negated)` |
| Similarity | Light stemming, stop-word removal, TF-IDF cosine |
| Conflict Engine | Pairwise comparison with three rules |
| CLI | `ingest`, `list`, `search`, `conflicts`, `report` |

## 5. Algorithms
- **Extraction patterns:** "we decided/agreed", "Decision:", "going with", "let's use/drop/switch", weak: "we will", "no longer", "from now on".
- **Polarity:** negation markers (`not, never, stop, drop, avoid, no longer`...).
- **option_swap:** both decisions have `use/adopt/switch to X` with different `X` and share at least one other topic token.
- **polarity_flip:** cosine >= 0.3 and negation differs.
- **number_change:** cosine >= 0.5 and numeric sets differ.
- Complexity: O(n^2) pairs; fine for V1 scale, replaced by ANN index in V2.

## 6. Implementation
Working code: `v1_impl/decisiongraph.py` (about 120 lines), tests in `v1_impl/test_decisiongraph.py`, sample notes in `v1_impl/sample_notes/`.

Sample output on the sample notes:
```
[option_swap]   PostgreSQL (2026-01-10) vs MongoDB (2026-03-02)
[number_change] rate limit 100 -> 300 per minute
[polarity_flip] "deploy every Friday" vs "stop deploying on Fridays"
```

## 7. Testing
- Unit: extraction on a mixed sentence (one decision, one chatter).
- Integration: sample notes must yield all three conflict kinds.
- Incremental: re-ingest leaves 6 decisions.
- Known gaps: sarcasm, implicit decisions, cross-sentence context, synonyms (handled in V2).

## 8. Acceptance criteria
- Tests pass; all three conflict kinds detected on sample data.
- Precision of extraction >= 70% on a hand-labeled set of 200 sentences (baseline for V2).

## 9. Risks
False positives from "we will" chatter (mitigated by confidence), O(n^2) cost, English only.

## 10. Exit to V2
Collect labeled data from real notes to train and evaluate better extraction.
