# V2: Understand (LLM Extraction, Embeddings, Review Queue)

**Problem fixed:** V1 rules miss implicit decisions and misread paraphrases ("Postgres" vs "PostgreSQL", "scrap" vs "drop").

## New features
1. **Structured extraction with an LLM** into a Decision schema: `title, statement, owner, date, scope, rationale, alternatives_considered, status, evidence_span, confidence`.
2. **Hybrid extractor:** V1 regex as a cheap recall filter, LLM as the precise parser; fall back to regex when offline.
3. **Embeddings + ANN index** (sentence embeddings, HNSW) replacing TF-IDF and the O(n^2) loop.
4. **NLI-based conflict classifier:** candidate pairs from ANN neighbors, then a model labels `contradiction / entailment / unrelated`, with an explanation.
5. **Human review queue:** low-confidence decisions and proposed conflicts go to accept/reject; feedback is stored as labels.
6. **Entity normalization:** alias table (`Postgres`=`PostgreSQL`), people and project resolution.

## Design
```
Ingestor -> Chunker -> Recall filter (regex) -> LLM Extractor -> Validator(JSON schema)
        -> Entity Resolver -> Store(SQLite->Postgres) + Vector Index
Candidate Generator(ANN) -> NLI Classifier -> Conflict Store -> Review Queue
```
- **Prompt contract:** system prompt requires JSON only, one decision per object, and a verbatim `evidence_span`; validator rejects any span not found in the source (anti-hallucination).
- **Model abstraction:** `Extractor` interface with `RegexExtractor`, `LLMExtractor(provider)`; provider chosen by config; cache by chunk hash.
- **Cost control:** only chunks passing the recall filter or containing decision keywords reach the LLM; batch requests; cache.

## Data model additions
`decisions(+title, owner, rationale, alternatives_json, status, evidence_span, embedding_id)`, `entities(id, canonical, aliases_json)`, `labels(decision_id, verdict, reviewer, ts)`, `conflicts(id, a, b, kind, score, explanation, state)`.

## Implementation steps
1. Define Pydantic schemas and migrate SQLite with a migration tool.
2. Implement `LLMExtractor` with retries, JSON repair and span validation.
3. Add the vector index (local HNSW library) with persisted ids.
4. Candidate generation: top-k neighbors above cosine 0.55, then NLI.
5. Build `dg review` terminal UI (accept, reject, edit).
6. Evaluation harness: precision/recall/F1 on the V1 labeled set.

## Testing and metrics
- Golden set of 500 labeled sentences; target F1 >= 0.85 for extraction, conflict precision >= 0.8.
- Regression test: any prompt change must not lower F1 on the golden set.
- Hallucination test: 100% of stored decisions have a verifiable evidence span.

## Risks
Model cost and drift, privacy of notes sent to a provider (offer local model mode), non-determinism (temperature 0, caching).
