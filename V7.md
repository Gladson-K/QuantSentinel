# V7: Measure (Decision Analytics and Org Health)

**Problem fixed:** Leaders cannot see how well the organization decides: reversals, re-litigation, slow decisions, orphaned ownership.

## New features
1. **Core metrics:** decision velocity (proposal to acceptance), reversal rate, re-litigation count (same topic decided again), conflict rate, stale-decision backlog, ownership coverage.
2. **Decision quality score:** completeness (rationale, assumptions, owner, review date) plus outcome signals (reversed early = negative).
3. **Topic clustering and heatmaps:** which areas churn the most.
4. **Decision debt:** count and age of decisions past review date or with broken assumptions.
5. **Team and org dashboards, trends, cohort comparisons**, exportable reports.
6. **Outcome tagging:** mark decisions as `worked / mixed / failed` after review to learn patterns.

## Design
- **Pipeline:** event log (`audit_events`) -> warehouse tables (daily snapshots) -> metrics layer (SQL models) -> dashboard API.
- **Metric definitions as code** (versioned SQL/dbt-style) so numbers are reproducible and auditable.
- **Clustering:** embeddings + HDBSCAN-style clustering, labeled by an LLM; stable cluster ids across runs via centroid matching.
- **Privacy:** metrics shown at team level with minimum group size; no individual performance ranking by default.

## Implementation steps
1. Event schema hardening and snapshot job.
2. Metrics layer with unit tests on synthetic org data.
3. Dashboard (charts, filters, drill-down to decisions).
4. Outcome tagging flow in review reminders.
5. Scheduled executive digest.

## Metrics of the metrics
Dashboard adoption by managers, correlation of decision quality score with later reversals (validity check), report generation under 5 seconds.

## Risks
Goodhart's law (people gaming completeness), surveillance perception (aggregate-only defaults, transparent definitions).
