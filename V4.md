# V4: Guard (Real-Time Conflict Prevention)

**Problem fixed:** Detection after the fact is late. The value peak is warning someone *before* they merge, announce, or build on a conflicting decision.

## New features
1. **GitHub App:** on PR open or update, compare the PR description, code comments and changed config values against stored decisions; comment with the conflicting decision, link and date.
2. **Slack bot:** when a message looks like a proposal ("let's switch to X"), reply privately with related prior decisions.
3. **Docs/IDE hint:** browser and editor extensions that surface "related decisions" for the paragraph or file in view.
4. **Decision guards as code:** users can pin rules, e.g. `dependency: forbid mongodb`, `config: rate_limit == 100`, linked to a decision and enforced as a CI check.
5. **Severity levels:** info (related), warn (probable conflict), block (guard rule violated, optional).
6. **Feedback buttons:** "not a conflict", "outdated", "yes, supersede it", feeding the review queue.

## Design
```
Event (PR/msg/doc) -> Trigger Router -> Query Builder -> Retrieval (ANN + filters by scope)
  -> Conflict Scorer (NLI + rules) -> Policy Engine (severity, quiet hours, dedupe)
  -> Notifier (PR comment / Slack ephemeral / CI status)
```
- **Latency budget:** under 3 seconds for chat hints (cache embeddings, scope filter first), under 60 seconds for PR checks.
- **Guard rule DSL:** YAML in repo `.decisionguard.yml`: `id, decision_ref, match (path glob, key, regex), assert`. A parser plus an evaluator runs in CI.
- **Noise control:** per-user rate limits, one comment per PR (updated in place), suppress after "not a conflict" feedback for that pair.

## Implementation steps
1. GitHub App with webhook receiver and signature verification.
2. Query builder: summarize PR diff to intent sentences with the LLM, embed, retrieve.
3. Scorer reuses V2 NLI; calibrate threshold using review feedback.
4. Guard DSL and CI action.
5. Slack ephemeral responder and opt-in channels.

## Testing and metrics
Replay history: run V4 on past PRs and count caught conflicts vs. known reversals; alert precision >= 0.75; mute/dismiss rate under 25%; p95 latency met; guard rules have unit tests and dry-run mode.

## Risks
Alert fatigue (conservative defaults, feedback loop), false blocks (block level off by default), leaking sensitive decisions into public repos (ACL check before quoting text).
