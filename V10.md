# V10: Ecosystem (Open Standard, Plugins, Decision Steward Agent)

**Vision:** Make decision memory a shared layer of work: an open format, a plugin economy, and an agent that actively stewards decision health.

## New features
1. **Open Decision Record (ODR) standard:** a versioned JSON/Markdown schema (id, statement, status, owner, rationale, assumptions, edges, evidence, signatures) with a reference validator and import/export for ADRs, RFCs and wiki pages.
2. **Plugin SDK and marketplace:** connectors, extractors (domain-specific: legal, medical ops, product, research), monitors, guard rules, dashboards; sandboxed execution with permissions manifest.
3. **Decision Steward agent:** continuously triages the graph: proposes merges, flags stale decisions, drafts supersession records, nudges owners, prepares review meetings. Human approval required for any write beyond drafts.
4. **Cross-organization benchmarks (opt-in, privacy-preserving):** anonymized metrics such as typical reversal rates by domain, using differential privacy.
5. **Federated decision sharing:** partners and open-source projects publish selected decisions to a shared graph with signed provenance.
6. **Domain packs:** pre-built assumption libraries and guard rules (security policy, data governance, clinical protocols, incident response).
7. **Public API and webhooks v2**, event streaming (Kafka-compatible), SDKs in major languages.

## Design
- **Plugin runtime:** WASM or container sandbox, capability-based permissions (read sources X, write drafts only), resource quotas, signed packages, review pipeline for marketplace listing.
- **Steward agent:** planner-executor loop over tools (search, impact, draft, notify), guardrails: action budget per day, approval gates, full action log, dry-run mode, kill switch.
- **Federation:** decision records signed with organization keys; verification via transparency log; consent and redaction mandatory before publishing.
- **Benchmarks:** noise added to aggregates (differential privacy), minimum cohort sizes, no raw decision text leaves a tenant.
- **Governance:** public RFC process for the ODR spec, conformance test suite, backward-compatibility policy.

## Implementation steps
1. Publish ODR v1 spec, validator, and converters; gather community feedback.
2. Plugin SDK, sandbox, and marketplace with signing.
3. Steward agent behind approval gates; pilot with design partners.
4. Benchmark pipeline with privacy review by an external auditor.
5. Federation prototype with open-source communities.

## Metrics
Number of third-party plugins, ODR adoption (tools importing/exporting), steward proposals accepted rate (target >= 60%), reduction in decision debt, retention of enterprise accounts.

## Risks
Spec fragmentation (governance and conformance tests), plugin supply-chain attacks (sandbox, signing, review), agent overreach (strict approvals and audit), privacy in benchmarks (formal DP accounting).

## End state
A decision layer for organizations: every important choice is captured, linked to its reasons, monitored for validity, and queryable with evidence, across tools and companies, on an open standard.
