# V6: Reason (Rationale and Assumption Graph)

**Problem fixed:** Conflict detection compares decisions to decisions. The deeper failure is that decisions rest on **assumptions** ("traffic stays under 1k rps", "vendor X is cheaper") that quietly stop being true.

## New features
1. **Assumption extraction:** each decision gets explicit assumptions, constraints and success criteria.
2. **Typed edges:** `depends_on`, `supersedes`, `conflicts_with`, `enables`, `blocked_by`, `derived_from`.
3. **Assumption monitors:** link an assumption to a measurable signal (metric query, price page, dependency version, policy document) with a threshold.
4. **Invalidation alerts:** when a monitor crosses its threshold, flag all dependent decisions and their owners ("this decision may be stale").
5. **Rationale cards:** options considered, criteria, trade-offs, who objected.
6. **Counterfactual notes:** "revisit if X" conditions captured at decision time.

## Design
```
Decision -> Assumption(id, text, monitor_ref, threshold, state)
Monitor Runner (scheduler) -> Signal Adapter (Prometheus/SQL/HTTP/RSS) -> Evaluator
   -> state change event -> Impact Resolver (graph traversal) -> Alerts + Staleness score
```
- **Graph storage:** PostgreSQL adjacency tables with recursive CTEs first; migrate to a graph DB only if traversal cost demands it.
- **Impact resolver:** BFS over `depends_on` edges up to depth N, weighting by edge confidence; output ranked affected decisions.
- **Signal adapters:** pluggable; each returns a value and timestamp; stored time series for audit.
- **Staleness score:** combines age vs. review date, assumption states, and number of newer related decisions.

## Implementation steps
1. Extend extraction prompt for assumptions and "revisit if" clauses; validate with evidence spans.
2. Add tables `assumptions, edges, monitors, signals`.
3. Monitor runner with backoff, secrets vault for credentials.
4. Graph UI: highlight broken assumptions in red and show blast radius.
5. Backtest on historical decisions with known reversals.

## Metrics
Percent of decisions with at least one assumption (target 60%), alert usefulness rating >= 4/5, share of reversals predicted by an assumption alert.

## Risks
Over-extraction of trivial assumptions (rank by impact), brittle monitors (health checks, "monitor unhealthy" state), privacy of metric credentials.
