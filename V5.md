# V5: Collaborate (Web App, Teams, Decision Lifecycle)

**Problem fixed:** A CLI and bots are not enough for teams; decisions need owners, states and review dates.

## New features
1. **Web app:** decision feed, search, graph view, detail page with evidence, history and comments.
2. **Lifecycle states:** `proposed -> accepted -> superseded | reversed | expired | archived`, with transitions logged.
3. **Owners and reviewers**, **review-by dates** ("revisit in 6 months"), reminder notifications.
4. **Workspaces, teams, RBAC:** admin, editor, viewer; visibility by team or source.
5. **Manual decision creation** and templates (lightweight ADR style).
6. **Supersession workflow:** accepting a conflict resolution links old and new, with a reason.
7. **Saved views, subscriptions, weekly digest email.**

## Design
- **Frontend:** React/TypeScript SPA; graph view with a force-directed layout; server-side pagination.
- **Backend:** REST/GraphQL API (FastAPI or similar), PostgreSQL, Redis for queues and cache, object storage for attachments, background worker service.
- **AuthN/Z:** OIDC login; RBAC checked in a policy layer; row-level security on workspace id.
- **State machine:** explicit transition table with guards (e.g. only owner or admin may accept); every transition writes an `audit_events` row.

## API sketch
`GET /decisions?q=&status=&team=`, `POST /decisions`, `POST /decisions/{id}/transition`, `GET /decisions/{id}/graph`, `POST /conflicts/{id}/resolve`, `GET /digest`.

## Implementation steps
1. Migrate to PostgreSQL; add `workspaces, users, memberships, audit_events`.
2. Build the API with OpenAPI spec and generated client.
3. UI: feed, detail, graph, review queue (ports V2 queue).
4. Notification service (email, Slack) with preference center.
5. E2E tests (Playwright) for core flows.

## Metrics
Weekly active teams, percent of decisions with an owner (target 80%), review-date compliance, time to resolve a conflict.

## Risks
Becoming "yet another wiki" (keep automation first, manual entry optional), permission complexity (centralize in one policy module with tests).
