# V3: Connect (Where Decisions Actually Live)

**Problem fixed:** Decisions are in Slack threads, PR reviews, Google Docs, meeting transcripts and tickets, not in folders of notes.

## New features
1. **Connectors:** Slack, GitHub (issues, PRs, review comments), Google Docs/Drive, Jira/Linear, Notion, meeting transcripts (Zoom/Meet/Teams exports), email (opt-in).
2. **Incremental sync** with cursors, webhooks and backfill jobs.
3. **Thread-aware extraction:** decide on a whole conversation (who agreed, final message), not isolated sentences.
4. **Source permalinks** on every decision; provenance retained.
5. **Dedup across sources:** the same decision announced in a meeting and a Slack recap becomes one node with multiple evidence links.

## Design
```
Connector Plugin (OAuth) -> Raw Event Queue -> Normalizer -> Thread Assembler
   -> Extractor (V2) -> Dedup/Merge -> Store
Scheduler (cron + webhooks) -> Sync State(cursor per source)
```
- **Connector interface:** `authorize()`, `list_changes(cursor)`, `fetch(item)`, `to_document(item) -> Document(text, author, ts, url, thread_id, acl)`.
- **Thread assembler:** groups messages by thread id and time window; extractor sees the thread plus participants and reactions (a thumbs-up counts as agreement signal).
- **Dedup:** embedding similarity + same entities + time window < 7 days; merge keeps earliest as canonical.
- **Queueing:** durable queue (e.g. Redis/SQS), idempotent workers, dead-letter queue, rate-limit aware backoff per provider.

## Security
OAuth scopes minimal read-only; tokens encrypted at rest; per-source ACL stored with each document; V3 only shows a decision to people who can see its source.

## Implementation steps
1. Define the connector SDK and a fake in-memory connector for tests.
2. Implement GitHub first (best APIs), then Slack, then Docs.
3. Build the sync state machine and webhook receiver.
4. Thread assembler + extractor changes; add `evidence[]` list per decision.
5. Dedup merger with an audit trail of merges (undo supported).

## Testing and metrics
Contract tests per connector with recorded fixtures; sync lag p95 under 5 minutes; duplicate rate under 5%; zero ACL leaks in permission tests.

## Risks
API rate limits and changes, noisy chat, privacy expectations (clear consent and per-channel allowlists).
